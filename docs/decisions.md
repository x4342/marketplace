# Engineering decisions

| Date | Decision | Reason |
| --- | --- | --- |
| 2026-11-22 | Use the system color scheme until a user selects Light or Dark using a server POST. Persist the selection in a first-party cookie. | The preference works without JavaScript and independently of authentication. |
| 2026-11-22 | Bind the development HTTP service and PostgreSQL host port to loopback. Load CSS and optional HTMX directly from local assets. | Keeps development isolated and avoids browser requests to third-party services. |
| 2026-11-22 | Use one PostgreSQL fixture to exercise the worker's heartbeat and the readiness probe's schema dependency. | Keeps M0 verifiable without introducing a job queue before a feature needs one. |
| 2026-11-22 | M1 uses canonical lowercase usernames, Argon2id, 12-hour opaque database sessions, five one-use recovery codes, and bounded account/action and process-wide authentication limits. Recovery replaces all prior sessions and codes. | Username-only identity works without email or tracking. Token digests and hashed passwords keep plaintext credentials out of PostgreSQL. Process-wide limits are intended for the single-process local milestone and should be reviewed before a production topology. |
| 2026-11-22 | M1 uses same-origin checks and first-party form tokens. Session and form cookies are HttpOnly and SameSite Strict, with Secure enabled on TLS requests. | Forms work without JavaScript, including in the loopback HTTP development environment. Production TLS termination and retention are release-review work. |
| 2026-11-22 | Discovery uses a simulated 1 EUR = 1.10 USD comparison rate dated 2026-11-22 with integer half-up rounding. It is labeled in the UI and stored separately from future payment quotes. | Reproducible local pricing behavior while the live FX source and quote terms remain open under X04. |
| 2026-11-22 | Seller drafts store bounded editable fields and an optional re-encoded thumbnail. Published listing and image updates are atomic. Draft revisions reject stale writes. | Incomplete drafts can be saved without weakening the published listing constraints. Product photos stay private until publication. Digital delivery payloads belong to fulfillment and use a separate access model. |
| 2026-11-22 | Message cursors are conversation-local and sends allocate the next position while locking the conversation. | Participants can page their history without exposing aggregate marketplace activity. Each send and its recipient notification commit together. |
| 2026-11-22 | M5 uses one unit per order, a 20-minute simulated quote at 100 TEST units per accounting cent, and a 48-hour manual task display deadline. In-stock items decrement on unpaid reservation and restore on expiry or cancellation. Automatic order snapshots capture an immutable plain-text delivery version. | Reproducible sandbox checkout without settling live asset, fee, FX, shipping retention, fulfillment, or dispute policies. |
| 2026-11-22 | Review eligibility requires a completed order and a stored verified simulated observation. Public averages require three visible reviews. Popular sorting uses at least three completed verified purchases for a listing. | Keeps small samples from driving ratings and keeps discovery based on real sandbox events. Thresholds are reversible presentation defaults. |
| 2026-11-22 | Seller insights count listing page loads without storing visitor IDs and exclude signed-in owner loads. Gross simulated sales group completed verified orders by original currency. | Separates engagement and sales estimates from the future financial ledger. |
